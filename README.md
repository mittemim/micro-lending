# Lending

Разрабатываем локальный одностраничный лендинг с одной формой заявки. Секции: Hero, «Плюсы», «Вопросы», «Форма». Якорная навигация переводит к нужной секции.

## Стек

- Next.js, React и TypeScript.
- npm как менеджер пакетов.
- App Router, исходный код в папке `src`.
- Обычный CSS без Tailwind.
- Zod для серверной проверки данных.
- SQLite как локальное файловое хранилище заявок.

## Форма и обработка данных

Форма содержит поля «Имя», Email и «Описание задачи». Состояние хранится на клиенте. Клиентская проверка выявляет пустые поля и некорректный формат email и показывает понятные ошибки.

После клиентской проверки данные отправляются в API-роут Next.js. Сервер повторно проверяет непустые имя и описание задачи и корректный email через Zod и сохраняет корректную заявку в локальный файл SQLite. Некорректные данные не сохраняются.

Сообщение об успехе появляется только после подтверждения сохранения сервером. Ошибки проверки, запроса или сохранения отображаются в форме; введённые данные сохраняются для исправления и повторной попытки.

## Текущее состояние

Реализованы секции лендинга, якорная навигация, форма с клиентской проверкой и отправкой в `POST /api/requests`. API проверяет данные через Zod и сохраняет заявку в SQLite. Успех возвращается только после записи; ошибки проверки возвращают `400`, ошибки сохранения — `500`.

## Локальная база данных

Файл базы: `data/requests.sqlite` относительно корня проекта `lending`. Папка, файл и таблица `requests` создаются автоматически при первой корректной отправке. Уже существующие записи сохраняются при повторном запуске.

Таблица содержит `id`, `name`, `email`, `description`, `created_at`. Время добавления хранится в UTC в формате ISO 8601. API возвращает `success`, `message`, проверенные поля в `data`, а также `id` и `createdAt` сохранённой записи.

Используется драйвер `sqlite3`. В Next.js он указан в `serverExternalPackages`, API работает в Node.js runtime. База и служебные файлы SQLite исключены из Git. Файл лежит вне `public` и не раздаётся как статический ресурс.

Проверки с отдельной временной базой, без изменения заявок проекта:

```bash
node --experimental-strip-types --test src/app/api/requests/route.test.mjs
```

## Запуск

Установить зависимости и запустить сервер разработки:

```bash
npm install
npm run dev
```

Открыть страницу в браузере по адресу, указанному в терминале (обычно http://localhost:3000).

## Критерии готовности

- Проект запускается командой `npm run dev`, главная страница открывается в браузере.
- Видны Hero, «Плюсы», «Вопросы» и форма; якорные ссылки работают.
- Форма принимает имя, email и описание задачи и показывает ошибки пустых полей и некорректного email.
- Данные отправляются в API-роут без перезагрузки страницы.
- Сервер проверяет данные через Zod, в том числе при обращении напрямую к API.
- Некорректные данные не сохраняются, API возвращает ошибки проверки.
- Корректная заявка сохраняется в локальный файл SQLite и остаётся в базе после перезапуска приложения.
- Сообщение об успехе появляется только после успешного сохранения; ошибки API или сохранения отображаются в форме.

## Ограничения

Один лендинг и одна сущность — заявка. Не добавляем авторизацию, деплой, дополнительные сущности или сложную архитектуру. SQLite используется локально; файл базы и его служебные файлы не должны попадать в Git.
